1. Alcance del documento

Este manual describe el procedimiento completo para poner en marcha el proyecto FlatShare en un entorno de desarrollo. Incluye la instalación del entorno Android, la configuración de Firebase, la aplicación de reglas, la compilación, la ejecución en dispositivo o emulador y la carga opcional de datos de prueba.

2. Requisitos previos

Elemento Requisito
Sistema Windows, macOS o Linux con soporte de desarrollo Android.
IDE Android Studio compatible con AGP 8.5.x.
JDK Java 17.
SDK Android compileSdk 35, targetSdk 35, minSdk 24.
Build Tools 36.1.0.
Firebase Proyecto con Authentication, Firestore y Storage habilitados.
Node.js Versión 18 o superior para el seeder opcional.

4. Estructura general del proyecto

  • app/: aplicación Android principal.
  • app/src/main/java/com/sergio/flatshare/features/: pantallas por dominio funcional.
  • app/src/main/java/com/sergio/flatshare/core/: sesión, ajustes, notificaciones y sincronización.
  • app/src/main/java/com/sergio/flatshare/shared/: utilidades y widgets reutilizables.
  • tools/firebase-admin-seed/: seeder para cuentas y datos de prueba.
  • firestore.rules: reglas de seguridad.
  • firestore.indexes.json: índices de Firestore.
  • firebase.json: configuración base de despliegue.

5. Clonar o abrir el proyecto

  1. Descargar o clonar el repositorio en local.
  2. Abrir Android Studio.
  3. Seleccionar File > Open.
  4. Elegir la carpeta raíz del proyecto.
  5. Esperar a que finalice el Gradle Sync.

6. Configuración de Android Studio

6.1 SDK y JDK

  • Instalar Android SDK Platform 35.
  • Instalar Build Tools 36.1.0.
  • Configurar Java 17 como JDK del proyecto.

6.2 Archivo gradle.properties

El proyecto ya incluye la configuración base:

org.gradle.jvmargs=-Xmx2048m -Dfile.encoding=UTF-8
org.gradle.problems.report=false
android.useAndroidX=true
android.nonTransitiveRClass=true

7. Configuración de Firebase

7.1 Crear y asociar el proyecto

  1. Entrar en Firebase Console.
  2. Crear un proyecto nuevo o reutilizar uno existente.
  3. Añadir una app Android con identificador com.sergio.flatshare.
  4. Descargar google-services.json.
  5. Copiarlo en app/google-services.json.
Importante: sin el archivo google-services.json la app no podrá conectarse con Firebase.

7.2 Authentication

En Authentication > Sign-in method debe activarse Email/Password. La app trabaja con verificación obligatoria de correo.

7.3 Firestore Database

  1. Ir a Firestore Database.
  2. Crear la base de datos en Native mode.
  3. Seleccionar la región del proyecto.
  4. Aplicar el contenido de firestore.rules.

7.4 Firebase Storage

Storage debe estar habilitado para soportar documentos y justificantes subidos desde la app. Es necesario especialmente para archivos asociados al piso y comprobantes de pago.

8. Reglas y seguridad

La instalación no estará completa si no se publican las reglas del proyecto. Las reglas actuales:

  • Restringen el acceso a usuarios autenticados y con correo verificado.
  • Limitan lectura de pisos a miembros del grupo.
  • Controlan aceptación de pagos pendientes por acreedor o propietario.
  • Permiten a miembros gestionar incidencias y horarios.
  • Reservan las reglas de la casa al propietario.

8.1 Aplicación manual de reglas

  1. Abrir Firebase Console.
  2. Entrar en Firestore Database.
  3. Ir a la pestaña Rules.
  4. Copiar el contenido de firestore.rules.
  5. Publicar.

8.2 Archivo firebase.json

El proyecto ya incluye esta referencia de despliegue:

{
  "firestore": {
    "rules": "firestore.rules",
    "indexes": "firestore.indexes.json"
  }
}

8.3 Índices Firestore

En el estado actual, el archivo firestore.indexes.json no define índices adicionales:

{
  "indexes": [],
  "fieldOverrides": []
}

9. Dependencias principales

  • AndroidX Core, AppCompat, Material y ConstraintLayout.
  • Firebase Auth, Firestore y Storage.
  • ML Kit Text Recognition para OCR.
  • ZXing para lectura y generación de QR.
  • libphonenumber para tratamiento de teléfonos.

10. Primera compilación

10.1 Desde Android Studio

  1. Esperar a que finalice el sync.
  2. Seleccionar emulador o dispositivo físico.
  3. Pulsar Run.

10.2 Desde terminal

gradlew.bat assembleDebug

En entornos Windows donde se use configuración aislada de Android/Gradle, puede ejecutarse:

$env:ANDROID_USER_HOME='C:\ruta\proyecto\.android-home'
$env:GRADLE_USER_HOME='C:\ruta\proyecto\.gradle-home'
.\gradlew.bat assembleDebug

11. Ejecución de la aplicación

La aplicación arranca desde SplashActivity. Durante el inicio:

  • Se crea el canal de notificaciones flatshare_reminders.
  • Se solicita POST_NOTIFICATIONS en Android 13 o superior.
  • Se verifica si existe sesión activa.
  • Si el correo no está verificado, la sesión se cierra y se redirige a login.

12. Permisos Android incluidos

Permiso Uso
INTERNET Comunicación con Firebase.
ACCESS_NETWORK_STATE Comprobación del estado de red.
POST_NOTIFICATIONS Recordatorios y avisos locales.
CAMERA Escaneo de códigos QR.

13. Seeder de datos de prueba

El proyecto incorpora un seeder en tools/firebase-admin-seed.

13.1 Requisitos

  • Node.js 18 o superior.
  • Archivo service-account.json del SDK Admin de Firebase.
  • Proyecto Firebase con Authentication y Firestore habilitados.

13.2 Instalación del seeder

cd tools/firebase-admin-seed
npm install
Página 6

13.3 Ejecución básica del seeder

node seed.js ^
  --service-account ./service-account.json ^
  --owner-email tu_owner@email.com ^
  --owner-password TuPasswordSegura123! ^
  --users 12 ^
  --groups 4 ^
  --rooms 3 ^
  --members-per-group 4 ^
  --expenses-per-group 8 ^
  --payments-per-group 6 ^
  --reminders-per-group 4

13.4 Presets incluidos

  • npm run seed:sergio-demo
  • npm run seed:sergio-owner-plus
  • npm run seed:sergio-tenant-plus
  • npm run seed:sergio-owner-homoerectus

El seeder genera un archivo de salida con las credenciales creadas en tools/firebase-admin-seed/output/.

14. Colecciones que crea o usa la aplicación

No es necesario crear colecciones manualmente. La app y el seeder generan automáticamente los documentos necesarios. Las colecciones principales son:

  • users
  • groups
  • group_codes
  • rooms_groups
  • expenses
  • payments
  • payment_deadlines
  • reminders
  • activity_logs
  • maintenance_tickets
  • house_rules
  • group_schedules
  • audit_events
  • invitations

15. Validación recomendada tras instalar

  1. Registrar un usuario con correo válido.
  2. Verificar el correo y entrar en la app.
  3. Crear un piso con habitaciones.
  4. Unirse a un piso con otro usuario por código o QR.
  5. Crear un gasto y completar un flujo de justificante.
  6. Crear un recordatorio y comprobarlo en calendario.
  7. Crear una incidencia y un horario desde Gestión.

16. Problemas frecuentes y solución

Problema Causa probable Solución
No compila el proyecto SDK o JDK incorrectos Verificar Java 17, compileSdk 35 y Build Tools 36.1.0.
Firebase no conecta Falta google-services.json Copiar el archivo en app/google-services.json.
No deja leer o guardar datos Reglas no desplegadas o correo no verificado Publicar firestore.rules y verificar el correo.
No se suben archivos Storage no habilitado Activar Firebase Storage y revisar su configuración.
El seeder falla Service account o Node incorrectos Instalar Node 18+ y comprobar el JSON del SDK Admin.

17. Observaciones técnicas

  • Todos los archivos de texto deben mantenerse en UTF-8.
  • Existe una advertencia conocida de compatibilidad de AGP 8.5.2 con compileSdk 35, aunque actualmente no bloquea la compilación.
  • Es recomendable mantener sincronizados firestore.rules, firestore.indexes.json y la documentación de Firebase.

18. Cierre

Una vez completados los pasos descritos, el proyecto queda operativo para desarrollo, pruebas y demostración. El entorno puede ampliarse con datos reales o con datos seed según las necesidades de validación.
