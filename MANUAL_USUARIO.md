# Manual de uso - FlatShare

## 1. Objetivo de este documento
Este manual de uso explica la aplicacion de forma sencilla, como si la persona que la lee no conociera el proyecto de antemano.

La idea es que sirva para:
- entender para que sirve cada pestaña;
- saber que botones hay en cada pantalla;
- saber que hacer en cada flujo;
- dejar espacio preparado para incluir capturas de pantalla en la memoria o en la entrega final.

## 2. Como usar este manual
La recomendacion es leerlo en este orden:
1. acceso a la app;
2. pestaña `Pisos`;
3. subpestañas internas del piso;
4. `Balance`;
5. `Calendario`;
6. `Perfil`;
7. `Ajustes`.

Cada apartado incluye:
- que se ve en pantalla;
- para que sirve;
- que puede hacer el usuario;
- un hueco pensado para meter una captura;
- un pie de figura sugerido.

## 3. Indice de capturas recomendadas

- entrar con su cuenta;

## 5. Vista general de la aplicacion
Una vez dentro, la app se organiza con una barra inferior principal.

Las pestañas principales son:
- `Pisos`
- `Balance`
- `Calendario`
- `Perfil`

Cada pestaña cumple una funcion distinta.

## 6. Pestaña Pisos
Esta pantalla recoge todos los pisos a los que pertenece el usuario.

### 6.1 Que se ve en esta pantalla
Normalmente se pueden ver:
- lista de pisos;
- botones para crear o unirse a un piso;
- buscador o elementos de apoyo visual;
- tarjetas con informacion resumida de cada piso.

### 6.2 Para que sirve
Sirve para:
- entrar a un piso;
- crear uno nuevo;
- unirse a uno ya existente;
- revisar informacion general antes de entrar.

### 6.3 Que puede hacer el usuario
Si es un usuario normal:
- entrar en un piso;
- unirse con codigo o QR;
- revisar la informacion del piso.

Si es propietario:
- crear piso;
- editarlo;
- eliminarlo;
- gestionar habitaciones y miembros.

## 7. Dentro de un piso
Cuando se entra en un piso, la app se reorganiza en varias subpestañas internas.

Las mas importantes son:
- `Movimientos`
- `Recordatorios`
- `Gestion`

## 8. Subpestaña Movimientos
Esta es la parte economica principal del piso.

### 8.1 Para que sirve
Sirve para controlar:
- gastos;
- pagos;
- justificantes;
- estados;
- vencimientos;
- deudas pendientes;
- gastos de habitacion cuando corresponda.

### 8.2 Que se ve en pantalla
En la parte superior suele haber:
- filtros rapidos por estado;
- boton `Filtros`;
- lista de movimientos debajo.

En la lista aparecen tarjetas con informacion como:
- quien solicita;
- para quien va;
- fecha del gasto;
- dia limite;
- importe;
- estado.

### 8.3 Estados que puede ver el usuario
Los estados visibles son:
- `Solicitado`
- `En revision`
- `Pagado`

Esto permite saber rapidamente en que punto esta cada movimiento.

### 8.4 Captura principal de movimientos
Captura recomendada:
- `Figura 6. Pantalla Movimientos con filtros rapidos y listado de gastos.`

Hueco para captura:
- insertar aqui una imagen de la subpestaña `Movimientos`.

### 8.5 Crear un gasto
Desde esta zona se puede abrir el dialogo de `Nuevo gasto`.

Ese flujo sirve para registrar:
- concepto;
- importe;
- categoria;
- prioridad;
- fecha limite;
- reparto;
- ticket.

Puntos importantes que conviene explicar junto a la captura:
- el ticket es obligatorio;
- el pagador no aparece como destinatario del reparto;
- el gasto puede quedar ligado a una o varias personas segun el reparto.

Captura recomendada:
- `Figura 7. Dialogo de Nuevo gasto.`

Hueco para captura:
- insertar aqui una imagen del dialogo `Nuevo gasto`.

### 8.6 Como explicar la tarjeta de un movimiento
Seria bueno añadir en el texto algo como:
- `Solicitado por`: indica quien creo o adelanto el gasto.
- `Para`: indica a quien afecta.
- `Fecha del gasto`: indica cuando se registró.
- `Dia limite`: indica hasta cuando deberia resolverse.
- Importe: muestra el valor economico.
- Estado: muestra si sigue pendiente, en revision o pagado.

## 15. Consejos para preparar las capturas del manual
Para que el manual quede limpio y uniforme:
- usa siempre el mismo dispositivo o resolucion;
- intenta que todas las capturas tengan la misma escala;
- evita poner notificaciones o datos irrelevantes;
- usa cuentas de prueba coherentes;
- procura que en cada imagen se vea claramente la funcionalidad explicada.

## 16. Formato recomendado para cada figura
Puedes repetir esta estructura en todo el documento:

`Figura X. Nombre de la pantalla o funcionalidad.`

Debajo de cada figura, explica en 3 bloques:
- que se ve;
- para que sirve;
- que puede hacer el usuario desde ahi.

## 17. Resumen final
Este manual queda preparado para crecer con capturas reales de la app.

La estructura pensada es:
- una explicacion facil;
- una imagen por pantalla importante;
- un pie de figura claro;
- una descripcion muy directa de cada funcionalidad.

Cuando se añadan las capturas, el documento ya tendra una base clara para presentar la app de forma visual, ordenada y facil de entender.
